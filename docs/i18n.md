# Internationalization

EqualEase defaults to standard macOS localization. Without an override, the app follows the user's macOS language order, including per-app language settings in System Settings when Apple exposes them for the installed app. This keeps the default language choice consistent with the rest of macOS.

A product experiment adds an optional in-app language override in Settings > General > Language. The override is only a preference for EqualEase, includes a System Default option to return to normal macOS behavior, and applies after the user quits and reopens the app. The menu-bar quick panel does not show language status.

## How localization is set up

- `EqualEase/EqualEase/Localizable.xcstrings` is the app string catalog for SwiftUI, model, status, notification, automation-error, and local-network remote copy.
- `EqualEase/EqualEase/InfoPlist.xcstrings` carries localized values for user-facing privacy usage descriptions.
- The source language and development region are English (`en`).
- String-catalog Swift symbol generation is disabled because EqualEase uses natural-language keys, punctuation, and duplicate short labels such as Volume/Input Volume.
- App Store metadata localization is handled outside this repository.

## Adding another language

1. Open the Xcode project.
2. Add the new language as a localization for the app target.
3. Translate `Localizable.xcstrings` and `InfoPlist.xcstrings` in Xcode.
4. Keep English source strings unchanged unless product copy intentionally changes.
5. Test with macOS language order, per-app language settings, System Default in Settings > General > Language, and the in-app override after relaunch.
6. Verify truncation and layout in the menu bar panel, Settings tabs, language picker, preset editor, pairing sheet, notifications, and phone remote.

## Translator notes

Keep EqualEase product terms consistent:

- **Routing** means system audio is captured locally, processed by EqualEase, then rendered to the selected real output device. It is not internet/network routing.
- **Process** means apply per-app volume plus global EQ/preamp processing.
- **Bypass** means audio still routes through EqualEase but skips EQ processing. Do not translate it as turning EqualEase off.
- **Preamp** is global output gain before final playback; preserve the audio-engineering meaning.
- **Preset** is a saved EQ curve and preamp level.
- **Mute** means silence one app stream.
- Output/input device names, app names, website hosts, bundle identifiers, URLs, percentages, and dB values are runtime values. Preserve placeholder order and units.
- Local-network remote copy is same-LAN pairing/security copy, not cloud account copy.

## Interpolated values and plurals

- Preserve placeholders exactly in Xcode's String Catalog editor.
- Keep `%`, `dB`, `Hz`, URLs, bundle IDs, and port numbers attached to their numeric/runtime values unless the target locale has a clear convention.
- Percentages such as `35%` and `100%` are user-facing control values.
- dB values are audio gain values; keep the `dB` unit.
- Current cleanup copy still uses `tap(s)` / `device(s)` instead of a plural rule. Add plural variations when adding the first non-English localization.

## QA checklist

- Build succeeds with `mise run build`.
- Tests pass or any skipped tests are documented.
- App launches in English when English is the active app/system language.
- Menu-bar panel preserves current English copy and behavior.
- Settings copy, alerts, accessibility labels, notification copy, and local-network pairing copy remain understandable.
- Runtime values render correctly: app names, website hosts, device names, percentages, dB/Hz values, times, and URLs.
